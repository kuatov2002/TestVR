# Конструктор учебных сценариев

Unity 6000.3, URP, новый Input System. Сторонних ассетов нет.

## Запуск

Открыть сцену `Assets/Scenario/Demo/ScenarioDemo.unity` и нажать Play. Слева выбрать «Тренировка» или «Экзамен» —
повторное нажатие перезапускает сценарий.

Игрок (синяя капсула) ходит на WASD. Кнопки и переключатель «Питание» справа нажимаются мышью.
На цветные зоны нужно встать, к ящикам и колоколу — подойти вплотную.
Зоны и предметы ещё не открытых шагов лучше обходить: заход в них засчитывается как нарушение вне очереди.

Слева список заданий и их статусы, внизу сообщения (красные — нарушения, зелёные — выполненные шаги).
После прохождения сверху появляется результат: там можно выбрать другой анализатор и нажать «Оценить заново».
Кнопка «Журнал» открывает журнал событий.

## Как настраивать сценарий

Всё находится под объектом `Сценарий` в иерархии, кода править не нужно.

**Шаги** — `Сценарий/Шаги`, компонент Action Step:
- `Id` — идентификатор для журнала, `Title` — текст задания;
- `Actions` — что нужно сделать, по порядку (S06 — сначала проходная, потом пульт), `Order Message` — сообщение при нарушении порядка;
- `Forbidden` — действия, которые считаются нарушением, пока шаг активен;
- `State Object` — объект, который должен быть включён (или выключен) в момент действия. Так сделан S07: «Пуск» засчитывается только при включённом питании.

Новый шаг удобнее всего сделать копией существующего (Ctrl+D), поменять поля и перетащить в группу нужного режима.

**Источники действий** — компоненты на объектах сцены:
- Button Action Source — нажатие UI-кнопки;
- Trigger Action Source — вход в триггер объекта с тегом `Required Tag` (по умолчанию Player);
- Collision Action Source — столкновение;
- Action Source — его метод `Raise` вешается на любой UnityEvent. Так подключён переключатель «Питание»
  (On Value Changed → `Индикатор питания.SetActive` и `Питание.Raise`).

**Режимы** — `Сценарий/Режим: тренировка` и `Сценарий/Режим: экзамен`:
- `Groups` — группы, идут друг за другом. Если у группы стоит `With Previous`, она стартует вместе с предыдущей;
- `Steps` в группе — порядок шагов, строки перетаскиваются мышью. Галочка «вместе с предыдущим» объединяет шаги
  в пачку, которая открывается одновременно; следующая пачка откроется, когда закончится текущая.
  В тренировке так собран пример из задания: 1–4 вместе, потом 5, 6, 7, 8 по одному, потом 9+10 и 11+12;
- `Out Of Turn` — действие шага, до которого не дошла очередь: нарушение (по умолчанию) или игнорировать;
- `Analyzer` — чем оценивать прохождение;
- `Violation Threshold` у экзамена — после скольких нарушений группа заканчивается (по умолчанию 2);
- `Finish Action` — действие, которое заканчивает прохождение досрочно. В экзамене это вход в белую зону «Выход»:
  ушёл из цеха — экзамен окончен, всё незавершённое становится Failed (шаги не выполнены). В тренировке поле пустое.

Шаги у режимов общие, в группах только ссылки на них, поэтому раскладки у режимов разные, а дублей нет.
Какие режимы доступны и какой запускать сразу при старте — у компонента Scenario Runner на объекте `Сценарий`.

**Логгеры и анализаторы.** Логгеры (`Сценарий/Логгеры`) подключаются списком `Loggers` у Scenario Runner:
Console Logger пишет в консоль, Json File Logger — в `scenario_log.jsonl` в `Application.persistentDataPath`.
Анализаторы лежат в `Сценарий/Анализатор: …`; у тренировочного настраиваются баллы за попытки, у экзаменационного — штрафы.
Список анализаторов для повторной оценки — поле `Analyzers` у Scenario View на объекте `UI`.
Сохранённый журнал можно оценить и без запуска: меню ⋮ на компоненте анализатора → «Оценить сохранённый журнал (JsonFileLogger)», результат в консоли.

## Оценка

Тренировка: при нарушении показывается причина, шаг повторяется, остальные активные шаги остаются активными.
За шаг 10 баллов с первой попытки, 5 со второй, 0 дальше; максимум 10 × число шагов.

Экзамен: нарушенный шаг сразу Failed. Когда в группе набирается порог нарушений, её незавершённые шаги становятся Skipped.
Итог = max(0, 100 − 10 × Failed − 5 × Skipped).
Действие шага из ещё не начатой группы проваливает только этот шаг: в порог нарушений оно не идёт
ни текущей группе, ни будущей.

Анализаторы работают только с журналом, поэтому любой можно применить к любому прохождению. Экзаменационный на журнале
тренировки считает шаги с нарушениями проваленными, тренировочный на журнале экзамена даёт 0 за проваленные и пропущенные.

## Проверка контрольных примеров на сцене

- Тренировка: «Надеть СИЗ» сразу (10); оранжевый ящик, потом синий (5); дважды в красную зону, потом на склад (0) — по этим шагам 15.
- Экзамен: в первой группе задеть оранжевый ящик и зайти в красную зону — S02 и S04 Failed, S01 и S03 Skipped, штраф 30.
  Дальше без ошибок — 70.
- Смешанная активация видна в тренировке: первые четыре шага в любом порядке, дальше по одному, в конце парами.
- S06: встать на пульт, не пройдя проходную, — нарушение порядка. S07: «Пуск» при выключенном питании — нарушение.
- «Стоп» в самом начале — нарушение вне очереди для S11; с `Out Of Turn` = «Игнорировать» ничего не происходит.
- Экзамен: сразу уйти в белую зону «Выход» — экзамен закончится, все шаги Failed, итог 0.

Эти случаи есть и в EditMode-тестах (`Assets/Scenario/Tests`, Window → General → Test Runner).

## Устройство

```
ActionSource → ScenarioRunner → ScenarioMode → Step
                    ├→ журнал (List<LogEntry>) → ScenarioLogger
                    └→ ResultAnalyzer (по журналу, после прохождения)
```

- `ActionSource` — превращает событие Unity в действие сценария.
- `Step` / `ActionStep` — логика одного шага: относится ли к нему действие, выполнен ли он, нарушен ли. Про режимы и очередь шаг ничего не знает.
- `ScenarioMode` — группы, пачки, статусы шагов, нарушения вне очереди. Что делать при нарушении, решают наследники:
  `TrainingMode` — повтор, `ExamMode` — Failed и порог.
- `ScenarioRunner` — связывает источники, режим, журнал и логгеры.
- `LogEntry` — запись журнала: `time` (секунды от старта), `stepId`, `type`, `result` и список `data` с доп. полями.
  Тип — строка, так что новые типы записей и поля не ломают существующие анализаторы.
  Пишутся `ScenarioStarted`, `GroupStarted`, `Action`, `StepActivated`, `Violation` (с номером попытки),
  `StepFinished` (Completed / Failed / Skipped, группа, число нарушений), `ScenarioFinished`.
- `ScenarioLogger` — получатель записей. Если логгер упадёт, ошибка уйдёт в консоль, прохождение не остановится.
- `ResultAnalyzer` — оценка по журналу. Если каких-то необязательных данных нет, в результат добавляется предупреждение.
- `ScenarioView` — интерфейс демо-сцены.

Расширение без правки существующего кода:
- новый тип шага — наследник `Step` (`Concerns`, `Handle`, при необходимости `ResetProgress`);
- новый источник — наследник `ActionSource`, вызывающий `Raise()`, или просто `Raise` на UnityEvent;
- новый режим — наследник `ScenarioMode` со своим `OnViolation`, добавить в `Modes`;
- новый логгер — наследник `ScenarioLogger`, добавить в `Loggers`;
- новый анализатор — наследник `ResultAnalyzer`, выбрать в режиме или в списке повторной оценки.

## Что улучшил бы дальше

- Шаги и режимы сейчас живут в сцене — так проще ссылаться на кнопки и триггеры, но сценарий не перенести в другую сцену.
  Дальше вынес бы описание сценария в ScriptableObject с привязкой к объектам сцены по id.
- Окно редактора с видом сценария и проверкой ошибок (шаг без действий, шаг в двух группах, пустые ссылки).
  В рамках тестового обошёлся стандартным инспектором и одним PropertyDrawer для строки шага.
- Условие у шага одно — «объект включён/выключен». Для сложной логики нужны подключаемые условия.
- Одновременные группы стартуют только вместе; старт группы посреди предыдущей не сделан.
- В UI видны последние 150 записей журнала (ограничение legacy Text), для длинных журналов нужен список с виртуализацией.
- Загрузка сохранённого журнала прямо из игры, а не только из редактора.

Графику и анимации не делал — по заданию они не оцениваются.
